# 題材重複調査レポート: `10.0` で登録した価格を `10.00` で検索できない

## 調査対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 基礎から実践 |
| 候補題材 | BigDecimalのスケールとMapキーの等価性 |
| 観測可能な契約 | `10.0` で登録したSKUを `10.00` で検索できるべきだが、HashMapのバグ状態では検索できない。 |
| 直接原因 | BigDecimalの `equals` が数値と表現を比較し、HashMapがその等価性でキーを照合する。 |
| カタログ更新日時 | 該当なし。`/home/ubuntu/repository-catalog/data/repositories.json` は環境内に存在しなかった。 |
| 検索語 | `BigDecimal`, `compareTo`, `scale`, `金額キー`, `金額の等価性` |

## 調査方法と制約

標準のRepository Catalogが環境に存在しなかったため、カタログ更新・検証と自動の語彙スコアリングは実施していない。代替として、ユーザー指定の `qiita` リポジトリ全体を `BigDecimal`、`compareTo(`、`scale(`、`金額キー`、`金額の等価性` で横断検索した。該当する既存記事は見つからなかった。

本レポートの結論は、利用可能なQiita記事群と、この作業環境で作成済みのラボに対する手動比較に限る。ユーザーの全リポジトリを網羅するカタログに基づく新規性主張ではない。

## 近接候補の比較

| 既存教材・記事 | 既存の直接原因 | 既存の実境界・最終観測 | 今回の差分 | 判定 |
| --- | --- | --- | --- | --- |
| `spring-transaction-self-invocation-lab` | 自己呼び出しがトランザクションプロキシを迂回する | 例外後の残高再読込 | 今回はJava標準ライブラリの等価性が原因であり、Map検索結果とキー表現を観測する。 | 重複なし |
| `spring-async-transaction-boundary-lab` | 非同期ワーカーがコミット前にデータを読む | ワーカーの可視性と最終状態 | 今回は非同期も永続化も使わず、同期的な価格キー検索を扱う。 | 重複なし |
| `spring-method-security-enable-lab` | `@EnableMethodSecurity` の不在 | 認可例外と承認状態 | 今回はセキュリティ設定ではなく、BigDecimalの値表現とJava Collectionsを扱う。 | 重複なし |
| Spring Data JPAの楽観ロック記事 | 楽観ロック不在または競合更新 | 在庫の永続化後状態 | 今回はJPAを使わず、単一プロセスのMapキー照合を扱う。 | 重複なし |

## 結論

作成する。

今回の題材は、直接原因がBigDecimalの数値比較と `equals` の差、実境界が `PriceCatalog#findSku`、観測契約が別スケールでのSKU検索、最小修正が数値順序を使うTreeMapへの変更である。既存のSpringトランザクション・非同期・認可・JPA競合更新の題材とは、原因、実境界、観測契約、修正の中心が異なる。
